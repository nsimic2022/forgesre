# ForgeSRE V0.6 — Operations hardening

**Status:** implemented on top of V0.1–V0.5  
**Depends on:** operator handbook (`docs/operator-handbook.md`), install guide (`docs/install-config.md`)

V0.5 shipped bundled snmp_exporter. V0.6 makes the appliance honest on a live DC: RCA no longer lies with demo gauges on real hosts, Alertmanager does not wait on the LLM, secrets fail closed, discovery classifies SNMP on UDP, and Linux hosts get real `node_exporter` alerts.

This is **not** the Go/K8s rewrite, not Alloy-instead-of-snmp_exporter, not Redis/Celery, not playbook execution, not bundled NetBox, not HA, not Alembic. Those stay in [`architecture.md`](architecture.md).

## What shipped

1. **RCA queries are asset-scoped.** Demo gauges (`forgesre_demo_cpu_percent` / `forgesre_demo_disk_percent`) overlay **only** for `forge-demo-01`. Linux hosts use `node_*` PromQL labeled `asset=…`. Network devices use `up{job="forgesre-snmp",asset=…}`.
2. **Fail closed on shipped secrets.** Core refuses to start if `SECRET_KEY` or `ALERTMANAGER_WEBHOOK_TOKEN` is still the repo default, unless `FORGESRE_DEV=1` (unit tests / explicit lab). `./forgesre secrets-check` reports the same. Committed Prometheus/Alertmanager YAML uses `CHANGE-ME-RENDER-MONITORING`.
3. **Jobs table + background RCA.** Alertmanager webhook creates the incident and enqueues `investigate`. A worker thread runs jobs every 2s so the webhook does not wait on ForgeRCA/LLM. Demo paths still run RCA inline if no investigation exists yet. CLI: `./forgesre jobs`.
4. **Incident numbering** uses `max(INC-N)+1`, not `count(*)+1`. A `resolved` alert closes an open incident and **does not** create a new one.
5. **HTML permissions match the API.** Viewer gets 403 on `/playrules`, `/playbooks`, `/escalation`, `/journal`, `/discovery`. Doctor requires a login session **or** `Authorization: Bearer ${ALERTMANAGER_WEBHOOK_TOKEN}`.
6. **Discovery.** TCP/161 is skipped. Classification uses an SNMPv2c GET on **UDP/161**. Approve assigns `:9100` only when port 9100 was open. SSH-only hosts become Linux **without** a scrape address. SNMP still wins over SSH when the UDP GET succeeds.
7. **Bundled `node_exporter` alerts** in `monitoring/alerts.yml`: `NodeExporterDown`, `NodeFilesystemUsageHigh`, `NodeCPUHigh`, plus the existing demo and SNMP rules. Seeded playrules `node-exporter-down` / `node-filesystem` / `node-cpu`. Extra site rules: `monitoring/alerts.local.yml` (gitignored; example committed). `./forgesre render-monitoring` writes `$FORGESRE_DATA/generated/alerts.yml`.
8. **Escalation policies are evaluated.** `process_escalations` reads the playrule’s policy steps. UI-created playrules attach `default-warning` if none is set.
9. **Permissions.** `data/` dirs are tightened at install (`postgres` included, `chown 70:70` when sudo works). Backups are `umask 077` / tar mode `600`. `./forgesre backup --no-secrets` omits `secrets.env`.
10. **Optional TLS.** Not a default Compose service. Example: `tls/Caddyfile.example`. Session cookie `Secure` when `system.cookie_secure: true` or `FORGESRE_COOKIE_SECURE=1`.

## Existing VM (do not re-run install.sh)

```bash
git pull origin main
./forgesre update
# same as: backup, render-monitoring, compose up, doctor
./forgesre secrets-check
./forgesre doctor
```

`render-monitoring` sets `FORGESRE_VERSION=0.6.0` and `PROMETHEUS_ALERTS` if missing, then rewrites generated Prometheus / Alertmanager / snmp / alerts YAML.

## CLI additions

```bash
./forgesre jobs            # background RCA queue
./forgesre incidents       # recent INC-… rows
./forgesre sd              # Linux + SNMP HTTP SD
./forgesre demo-reset      # lower demo CPU/disk gauges
./forgesre secrets-check   # shipped-default SECRET_KEY / webhook token
./forgesre backup --no-secrets
./forgesre help tls
./forgesre version
```
