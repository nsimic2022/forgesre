# ForgeSRE V0.7 — Incident history

**Status:** implemented on top of V0.1–V0.6  
**Depends on:** operator handbook (`docs/operator-handbook.md`), install guide (`docs/install-config.md`)

V0.6 hardened operations. V0.7 adds a 90-day incident history view so operators can find closed work, see who Ack/Resolve-d, read the mail outbox for that `INC`, and leave a short note about what they actually did on the host.

This is **not** a rewrite of Incidents, Escalation, or Console. Those screens stay. History reads the same Postgres rows with a date window and extra fields on the incident page.

This is **not** the Go/K8s rewrite, not Alloy-instead-of-snmp_exporter, not Redis/Celery, not playbook execution, not bundled NetBox, not HA, not Alembic. Those stay in [`architecture.md`](architecture.md).

## What shipped

1. **History menu** at `/history`. Default lookback is **90 days** (cap 10 years). Filters: status, asset/hostname/IP, incident number. List is paginated (200 per page). Closed rows stay here; Incidents is still the live list (last 200, no date filter).
2. **Incident page** shows Ack actor/time, Resolve/Close actor/time, the **email outbox for that incident** (not only the last 20 on Escalation), **audit rows for that `INC`**, and **operator notes**.
3. **Operator notes** (`incident_notes`). Short comments such as “cleaned WAL”. Not a ticket thread, not the playbook, not RCA. Analyst+ (`write_incidents`) can add them. Empty notes are rejected.
4. **API:** `GET /api/v1/history`, `GET /api/v1/incidents/{number}` includes `notifications` / `audit` / `notes`, `POST /api/v1/incidents/{number}/notes`. Status changes record `ack_by` / `resolved_by`.
5. **CLI:** `./forgesre history` (filters `--days` / `--status` / `--asset`). `./forgesre history INC-000012` prints mail, audit, and notes. `./forgesre` with no args (or `./forgesre shell`) is a prompt: type `history` / `journal` without repeating `./forgesre`. `./f` is the same command under a shorter name.
6. **Appliance version** is `0.7.0` (`FORGESRE_VERSION`, FastAPI `version`, CLI fallback).

Data was already in Postgres. V0.7 is the GUI/API/CLI to look at it.

## Existing VM (do not re-run install.sh)

```bash
git pull origin main
./forgesre update
./forgesre doctor
```

Core migrate adds `incident_notes` and `incidents.resolved_by` / `resolved_at`. No install.sh.

## CLI

```bash
./forgesre history
./forgesre history --days 90
./forgesre history --status CLOSED
./forgesre history --asset db-01
./forgesre history INC-000012
./forgesre help history
```
