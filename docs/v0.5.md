# ForgeSRE V0.5 — Bundled snmp_exporter

**Status:** implemented on top of V0.1–V0.4  
**Depends on:** inventory HTTP SD (`docs/v0.2.md`), operator handbook (`docs/operator-handbook.md`)

V0.4 did **not** ship snmp_exporter. Discovery TCP/161 only classified “Possible network device”. V0.5 adds a **bundled `prom/snmp-exporter` container** on host network (`127.0.0.1:9116`) and a Prometheus job that SNMP-walks approved network devices.

## What shipped

- Compose service **`snmp-exporter`** (`prom/snmp-exporter:v0.26.0`), host networking, config from `$FORGESRE_DATA/generated/snmp.yml`.
- Prometheus job **`forgesre-snmp`**: HTTP SD `GET /api/v1/sd/snmp` → relabel `__param_target` → scrape `127.0.0.1:9116/snmp?module=if_mib&auth=public_v2`.
- SNMP targets are **network devices with an IP**. Linux `node_exporter` hosts stay on `/api/v1/sd/prometheus` (`:9100`) and are **never** SNMP-scraped.
- Compact IF-MIB walk (sysDescr, sysUpTime, ifAdmin/ifOper, ifName, ifHCIn/OutOctets, ifHighSpeed, ifAlias).
- Alerts: `SnmpDeviceUnreachable` (`up{job="forgesre-snmp"} == 0` for 2m), `NetworkInterfaceDown` (ifOper down / ifAdmin up).
- Playbook `NETWORK-UNREACHABLE` and playrule `snmp-down`.
- CLI: `./forgesre snmp`, `./forgesre assets`, `./forgesre render-monitoring`, `./forgesre help [command]`.
- Doctor component `snmp`. Console module `snmp` when a network asset is added.

## Linux vs network

| Kind | How it is monitored | Ports |
|---|---|---|
| Linux server | Prometheus scrapes **node_exporter** at `scrape_address` (`ip:9100`) | TCP 9100 to the host |
| Network device | snmp_exporter on the ForgeSRE VM walks **UDP/161** on the device IP | UDP 161 from this VM to the device |

Discovery still probes **TCP** 161 to classify. SNMP polling is UDP. An empty SNMP SD list is normal until you add a Network device with an IP.

## Existing VM (do not re-run install.sh)

```bash
git pull origin main
./forgesre render-monitoring
docker compose up -d
./forgesre doctor
./forgesre snmp
```

`render-monitoring` writes generated Prometheus/Alertmanager/snmp.yml, appends `SNMP_COMMUNITY=public` if missing, and sets `SNMP_EXPORTER_CONFIG`. Then add a switch: Assets → type `Network device` + IP → `./forgesre snmp`.

## Community and firewall

- Default community `public` in `secrets/secrets.env` (`SNMP_COMMUNITY`). Production: set the real read-only community and re-run `./forgesre render-monitoring`.
- Device ACL must allow the ForgeSRE host. Host firewall must allow **outbound UDP/161**.
- `up{job="forgesre-snmp"}==0` means the walk failed (wrong community, ACL, or device down), not that Prometheus is down.

## Not in this slice

Still no SNMPv3 UI, no full vendor MIB pack, no auto-remediation, no bundled NetBox. Alloy remains the longer-term collector in `docs/architecture.md`; V0.5 ships standalone snmp_exporter because that is what operators run today.
