# ForgeSRE V0.8 (history) — Appliance NET, journal list, NOC asset fields

**Status:** shipped. Current product is **V0.9** — see [`v0.9.md`](v0.9.md).  
**Depends on:** operator handbook (`docs/operator-handbook.md`), install guide (`docs/install-config.md`)

V0.7 added incident history. V0.8 is a small operator slice: the Dashboard tells you whether **this ForgeSRE VM** has a network path, and Add / Edit asset carries the NOC facts a person on shift needs before picking up the phone. The Journal list is on System Health; the Dashboard no longer shows a journal preview.

This is **not** a new exporter stack, not NetBox write-back, not a PromQL editor, and not playbook execution. At the time of V0.8, [`architecture.md`](architecture.md) was still a proposal. It now describes the V0.9 appliance.

## What shipped

1. **Version 0.8.0** — GUI sidebar `v0.8`, FastAPI `version`, `FORGESRE_VERSION` in `.env` (written by `./forgesre update` via render-monitoring), CLI `./forgesre version` fallback.
2. **Dashboard → This appliance → NET.** One dash like CPU / RAM / HDD.
   - **Green:** this VM has an IPv4 (or, if none, IPv6) **default route** on a non-docker interface and that interface's link is **up** (`/sys/class/net/<iface>/operstate`, carrier when operstate is `unknown`).
   - **Red:** no usable default route, or the interface carrying it is down, or `/proc/net/route` is unreadable.
   - Reading: `ens160 up · gw 10.10.10.1`, `no default route`, or `ens160 down`.
   - No ping and no internet probe. An air-gapped lab with a LAN gateway is green; ForgeSRE cannot cheaply tell "LAN only" from "internet", so it does not pretend to. Core uses `network_mode: host`, so `/proc/net` and `/sys/class/net` are the VM's own. Docker bridges (`docker0`, `br-*`, `veth*`) are ignored.
   - `GET /api/v1/system/resources` adds `net` (`level`, `iface`, `gateway`, `family`, `link`, `reading`, `detail`) and `levels.net`.
3. **Journal list** uses the same list chrome as other lists: left row checkboxes (`name="selected"`, header selects the page), `Showing 1–10 of N`, **Rows** 10 / 20 / 50 / 100 on the right. It lives only on **System Health** (`/health-ui#journal`). The Dashboard does not show Recent journal reports.
4. **Add / Edit asset** is two columns.
   - **Left:** *Identity* (Asset ID, hostname, IP, type, environment, scrape address, Customer / domain, Site / DC / room, notes) and *NOC contacts* (owner / team, contact, owner email, owner phone, Backup on-call name / phone / email, Support hours, Timezone, License / contract / SLA, Runbook note).
   - **Right:** *Standard alarms* (CPU / memory / disk / up — still mute-only, still cannot fire earlier than `alerts.yml`) and *Client playrules*.
   - New text fields are stored in `assets.extras` (JSON). Clone copies them (new Asset ID only). They are never written to NetBox.
   - Incident **Who to call** shows the filled fields; the Runbook note is a highlighted block under it. Escalation mail (plain + HTML) lists them too. Escalation role steps still mail **Owner email only** — the backup contact is for the human, not an automatic second recipient.
5. **Client playrules** (`assets.playrule_ids`, JSON list of playrule ids).
   - Does **not** create Prometheus thresholds and does not evaluate metric / operator / value.
   - When an alert opens a **new** incident for this asset, Core first tries the ticked playrules in saved order; the first **enabled** one whose alertname equals the alert's alertname is used (its playbook and escalation policy follow). The incident timeline says `PLAYRULE <name> (asset client playrule)`.
   - Nothing ticked, or no ticked rule matches that alertname → the global match, unchanged: first enabled playrule (by id) with that alertname.
   - Deleted playrule ids are dropped on the next save; disabled ones are skipped at match time.
   - API: `extras` and `playrule_ids` on `POST /api/v1/assets`, `POST /api/v1/assets/{id}`, `POST /api/v1/assets/{id}/clone`, and in every asset JSON.

6. **Asset VLAN + per-asset SNMP auth (v08-16).**
   - **VLAN** (free text, `10` or `10.20`) on Add / Edit next to Site, on the asset page (`—` when empty), in Search, and as an Assets filter dropdown (`/assets?vlan=10`, distinct values + *All VLANs*). Stored in `assets.extras.vlan`.
   - **SNMP version** v1 / v2c / v3 under SNMP port. **Community** Default (`SNMP_COMMUNITY`, `public_v2` / `public_v1`) or Custom. v3: username, security level, auth / privacy protocol + password. Secrets are never echoed in HTML, the asset API, Journal or audit.
   - Custom community and v3 become a real snmp_exporter auth `forgesre_<asset id>` once `./forgesre snmp-auths` (also run by `update` / `render-monitoring`) writes it into `data/generated/snmp.yml`. Until then SD keeps `public_v2` and the asset page says *pending*.
   - Add / Edit layout: left Identity + NOC; middle **only** Comms / monitoring with reserved space below; right Standard alarms, a rule, then Client playrules.

## Existing VM (do not re-run install.sh)

```bash
git pull origin main
./forgesre update
./forgesre doctor
./forgesre version   # 0.8.0
```

Core migrate adds `assets.extras` and `assets.playrule_ids` (nullable JSON). Existing rows read as empty. No install.sh.

## Not in V0.8

- Network throughput or packet-loss graphs for the appliance.
- Mailing the backup on-call automatically.
- Per-asset PromQL or thresholds that fire earlier than `monitoring/alerts.yml`.

Optional Zabbix (read-only, second ingest path) is operator-documented in [`zabbix.md`](zabbix.md), not a V0.8 feature slice. Grafana is still not in the alarm path.
