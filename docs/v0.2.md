# ForgeSRE V0.2 — Discovery and inventory

**Status:** active for V0.2  
**Date:** 2026-08-20  
**Depends on:** V0.1 vertical slice (`docs/v0.1.md`)

V0.2 adds a working inventory path: semi-automatic discovery, Prometheus HTTP service discovery, and optional **external** NetBox. It does not replace NetBox, nmap, or Netdisco.

---

## 1. What this slice must do

```
scan CIDR (TCP probe)
  → NEW DEVICE DETECTED
  → Approve / Ignore
  → approved Linux host appears as an asset
  → Prometheus HTTP SD picks up {ip}:9100
```

Manual assets still work. The V0.1 demo path is unchanged: Core is still scraped by a **static** Prometheus job so HighCPU keeps working if HTTP SD is empty or Core was briefly down.

---

## 2. Decisions (where V0.2 disagrees with the long-term proposal)

| Topic | Phase 0 proposal | V0.2 | Why |
|---|---|---|---|
| Discovery process | Separate privileged container | **In-process in Core** (`agents/discovery.py`) | One fewer container to debug; V0.2 is a TCP probe, not a packet capture suite |
| NetBox | Bundled overlay (NetBox + Redis) | **External only** | Redis would exist only for NetBox. Operators who already have NetBox point ForgeSRE at it |
| Scanner | nmap / Netdisco-class | **Ports 22, 80, 443, 161, 9100** | Enough to classify Linux / network / web. Full SNMP inventory is later |
| Unreachable hosts | Alert `up == 0` | **No** | Discovered hosts often have no node_exporter yet; that alert would be noise |
| Approve writes NetBox | Optional | **Off** | Creating NetBox devices needs site/role/type. V0.2 is read-sync + local approve |
| Loopback | Unspecified | **Skip 127.0.0.0/8** | Do not “discover” the appliance itself |

AI stays read-only. Discovery does not call the LLM.

## 3. How it works

### Candidates

`discovery_candidates` rows are not assets. Status is `new`, `approved`, or `ignored`. Approving creates (or links) an `assets` row with `source=discovery`. Linux-looking hosts get `scrape_address={ip}:9100`. Network devices get an empty scrape address.

The demo seeds `10.20.30.41` (“Possible Linux server”, ports 22 and 9100) so `/discovery` has something to Approve without a live CIDR.

### Scanner

`agents/discovery.py` expands CIDRs (max 256 hosts), skips loopback/multicast, and probes TCP. Classification:

- 22 or 9100 → Possible Linux server
- 161 → Possible network device
- 80 or 443 → Possible web/appliance

Mode:

- `semi-automatic` (default): candidates wait for a human
- `automatic`: still writes an audit row (`actor=system-automatic`) then approves
- `manual`: no background scan; **Scan now** still works

Background loop: first scan ~30s after Core start, then every 6 hours.

### Prometheus HTTP SD

`GET /api/v1/sd/prometheus` with `Authorization: Bearer $ALERTMANAGER_WEBHOOK_TOKEN` returns inventory scrape targets only. Core stays on `static_configs` in `monitoring/prometheus.yml.tpl` so the demo scrape does not depend on HTTP SD and is not double-scraped.

### NetBox

If `inventory.netbox.enabled` is true, Core pulls `/api/dcim/devices/` with `NETBOX_API_TOKEN` and upserts local assets (`source=netbox`). Doctor reports NetBox as `disabled` when it is off, or `error` with a curl test when it is on but unreachable. Core never writes to NetBox in V0.2.

## 4. Operator surface

| Path | Purpose |
|---|---|
| `/discovery` | Candidates, **NEW DEVICE DETECTED**, Approve / Ignore, Scan now |
| `/assets` | Inventory plus a manual create form |
| `/api/v1/sd/prometheus` | Prometheus HTTP SD |
| `/api/v1/discovery/*` | Same actions as JSON |

Config lives in `config/forgesre.yml`. The token is in `secrets/secrets.env` (`NETBOX_API_TOKEN=`, `ALERTMANAGER_WEBHOOK_TOKEN=`).

```bash
./install.sh --non-interactive --profile standard --port 8080
./forgesre demo
# login → Discovery → Approve 10.20.30.41 → asset disc-10-20-30-41
./doctor.sh
```

---

## 5. Not in V0.2

SNMP walk, Netdisco, bundled NetBox, write-back to NetBox, `up == 0` for discovered hosts, Visual Agent, extra LLM agents.
