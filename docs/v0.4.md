# ForgeSRE V0.4 — Asset contacts and first-hour demo

**Status:** implemented on top of V0.1–V0.3  
**Depends on:** inventory (`docs/v0.2.md`), RCA (`docs/v0.3.md`)

V0.4 is an operations increment. It does not change the monitoring stack.

## What shipped

- **Analysts can add and edit assets** (`write_assets`). They still cannot see PromQL/LogQL or Administration.
- **Owner contacts on every asset:** team, contact name, email, phone, notes.
- **Edit after Save.** Hostname/`asset_id` stay put; owner, contacts, IP, environment, scrape address, and notes can change.
- **Escalation uses the asset owner email** when it is set. SMTP still optional; the generated-notification log is the lab outbox. Fallback remains `<role>@forgesre.local`.
- **Similar-incident history** on the asset page (grouped by alert/title) and a compact list on the incident page.
- **First-hour walkthrough** on the dashboard. Seed fills `forge-demo-01` with contacts and a closed HighCPU row so a user sees the shape immediately after install. `./forgesre demo` then opens a live HighCPU and notifies `platform@forgesre.local`.
- **Console** (`/journal`): each module writes a short ok/warn/error report (install, seed, inventory, discovery, incident, RCA, notification, demo). The journal is split by module and pruned automatically (~200 rows each) so search stays small. Not a Docker log dump; not the admin audit log.

## Operator path

After install (do not re-run `./install.sh` on a live box):

```bash
./doctor.sh
# login at :8080 → Dashboard walkthrough → Assets / forge-demo-01 → Console
./forgesre demo
# incident → Who to call → Escalation → asset similar history → Console
./forgesre journal
```

## Not in this slice

Still no auto-remediation, no bundled NetBox, no GGUF in git, no UI to delete assets or edit users.

SNMP polling of network devices is **V0.5** ([`v0.5.md`](v0.5.md)), not this slice.
