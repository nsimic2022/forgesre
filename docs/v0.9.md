# ForgeSRE V0.9 — current appliance

**Status:** current product (`0.9.0`)  
**History:** [V0.1](v0.1.md) through [V0.8](v0.8.md) stay as release notes. This file is the slice you are running.  
**How it is built:** [architecture.md](architecture.md). **How you run it:** [operator-handbook.md](operator-handbook.md).

V0.9 is the same Compose appliance as V0.8, with the operator surfaces that landed after that note: device syslog, Rules, the per-asset Escalation steps, the Escalated count, and one Incidents list.

## What you use now

1. **Version 0.9.0** — sidebar `v0.9`, FastAPI `version`, `FORGESRE_VERSION` in `.env.example` (written by `./forgesre update` via render-monitoring), CLI `./forgesre version`.
2. **Syslog and Loki** — devices send syslog to Alloy on UDP/TCP **514**. Lines are labeled by hostname and sender IP and stored in Loki. Loki is **logs** for incident evidence. Demo Core logs stay on `forge-demo-01`.
3. **Rules** (`/playrules`) — match **alertname** after ingest and attach a Playbook plus the default escalation. PromQL stays in `monitoring/alerts.yml`. Operators run the Playbook checklist.
4. **Alarms** — per-asset mute (and a threshold note) for bundled Prometheus alerts. Mute skips **ingest** of that alert. Host metrics keep drawing.
5. **Custom alarms** — per-asset rule list. The first ON rule with the same alertname wins over the Rules page. OFF skips that rule on this host only.
6. **Escalation** — per-asset mail steps (L1–L4). Empty uses the Default escalation. Email only. Acknowledge stops the climb.
7. **Escalated** — incidents that have climbed stay status `ESCALATED`. The Dashboard Incidents tile counts them. JSON acknowledge keeps that status.
8. **History** — `/history` redirects to **Incidents**, which lists every status.
9. **Host metrics** — Asset page, Dashboard (the one selected Recent incident), and the incident page chart Prometheus `query_range` (SD `job` + `instance`, or the SNMP target). The asset page is the last hour for that host, healthy or in problem. An incident chart runs from one hour before it started through now, or through the end if it is resolved, with a vertical line at When. Zabbix `trend.get` is the fallback when Prometheus has no samples. **Not scraped.** / **No samples yet.** / **Steady.** Mute leaves the chart as-is. The Host metrics *title* sits above the cube so it lines up with Recent incidents.
10. **On call** — Dashboard line + `/escalation#oncall` weekly roster. **I'm on duty now** writes today's remaining window as the logged-in user (later start wins).
11. **List export** — every pager Export is **TXT** or **CSV UTF-8** (BOM). The incident title column is **Incident**. Browser local time stays in the nav.
12. **ForgeAI digest** — Dashboard strip under Recent incidents. SQL facts first; optional LLM sentences; Report TXT/CSV or mail. DEMO rows stay out of the digest. Ingest still follows Prometheus → Alertmanager → Core.
13. **LibreNMS Discovery SNMP** — bundled LibreNMS (`:8000`) identifies vendor/model/ports/sensors. Core maps that onto a bounded OID catalog, writes snmp_exporter `forgesre_onboard`, and Prometheus job `forgesre-snmp-onboard` scrapes only applied assets. LibreNMS polling is off after Identify.

## Existing VM

```bash
git pull origin main
./forgesre update
./forgesre doctor
./forgesre version   # 0.9.0
```

`./install.sh` is the first-install path.

## How this appliance runs

- One Core process, one jobs thread (Postgres `jobs` table: RCA, `discovery_scan`, reports).
- Playbooks are checklists the operator follows.
- NetBox and Zabbix are read sources. Core authenticates to NetBox with `NETBOX_API_TOKEN`.
